# 澄清契约

## 标题
新增工作流审计计划，聚焦重复文档、职责重叠与 token 浪费

## 摘要
- 在 Phase 4 收口后，为模板仓库启动下一轮工作流审计。
- 审计目标聚焦重复文档问题、职责重叠 / 模糊问题、token 浪费问题。
- 本任务需要沉淀为独立执行计划，而不是继续堆入当前治理升级计划。

## 任务类型
feature

## 目标结果
产出一份新的执行计划，系统梳理仓库中文档与工作流的重复、职责边界模糊和长期上下文浪费问题，并定义后续治理顺序。

## 问题 / 缺口
当前 Phase 4 已基本把 repo-local 澄清、交接与 hooks 基线稳定下来，但还没有独立计划去系统性审计文档重复、职责交叉和 token 成本来源。

## 当前证据 / 信号
- `AGENTS.md`、`docs/` 索引、`templates/`、`.github/prompts/` 与 `skills/` 之间已经完成一轮职责收敛。
- 当前活动计划已把“下一份工作流检查计划”标记为 Phase 4 完成后的后续动作。
- 下一轮治理目标已被用户明确指定：重复文档、职责重叠 / 模糊、token 浪费。

## 范围
- 定义新的工作流审计计划的目标、范围、验证和风险。
- 聚焦重复文档、职责重叠 / 模糊、token 浪费三类问题。
- 明确下一轮审计只做发现、分类与治理计划，不混入大规模修复。

## 非范围
- 本任务不直接批量修正文档。
- 本任务不重开 Phase 4 已稳定的澄清 / handoff / hooks 基线讨论。
- 本任务不把新审计计划与当前治理升级计划混写为同一份文档。

## 约束与禁止
- 必须使用独立执行计划承载下一轮审计。
- 新计划必须先写质量门禁、验证和风险，再写实现步骤。
- 不得把“发现问题”和“批量修复问题”混成同一阶段。

## 验收标准
- 已生成独立执行计划文件。
- 新计划明确覆盖重复文档、职责重叠 / 模糊、token 浪费三类问题。
- 新计划的验证方式和证据记录方式明确，不依赖口头约定。

## 验证计划
- 测试：不适用。
- 手动步骤：核对新计划是否独立成文、边界清晰、质量控制章节完整。
- 日志 / 截图 / 指标：记录计划文件路径及文档检查结果。

## 风险
- 若审计计划边界不清，容易再次与旧计划职责重叠。
- 若过早进入修复，会重新混合“审计”和“实施”目标。

## 假设
- Phase 4 在本轮验证后可标记完成。
- 下一轮工作适合从独立计划开始，而不是直接开始零散修补。

## 未决问题
- 审计计划是否只做文档与工作流层，还是同时覆盖 `.github/hooks` 与 `.vscode/settings.json` 的 token 成本。
